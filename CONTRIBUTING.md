# Contributing to Brasa

Thanks for helping make Brasa better. This document covers the local workflow,
the quality bar and the conventions that keep the theme consistent.

## Ground rules

- Stay inside the repository. Never push, publish or deploy.
- No lorem ipsum, placeholders, TODOs or half-finished pages. Demo copy must be
  realistic and available in both English and pt-BR.
- Do not add external image hotlinks or UI frameworks. Visuals are CSS/SVG;
  interactivity is vanilla TypeScript.
- Commit with [Conventional Commits](https://www.conventionalcommits.org/):
  `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`.

## Getting started

```sh
git clone https://github.com/hadagalberto/brasa.git
cd brasa
npm install
npm run dev
```

Node 20 or newer is required. The site is served at `http://localhost:4321`.

## Before you open a pull request

Run the full gate locally — CI runs the same commands on Linux, macOS and
Windows:

```sh
npm run format          # Prettier, Astro + Tailwind class sorting, LF endings
npm run check           # astro check: 0 errors, 0 warnings
npm run lint            # ESLint
npm run build           # verify MDX, build to dist/, prepare + index Pagefind
npm run test            # Playwright + axe against dist/
npm run lhci            # Lighthouse CI, mobile + desktop (≥ 0.98 each)
```

Always build before testing: Playwright and Lighthouse serve `dist/`. The
Playwright config pins `127.0.0.1` so the server is reachable on every OS.

## Where things live

| Change                                          | File(s)                                                            |
| ----------------------------------------------- | ------------------------------------------------------------------ |
| Identity, nav, footer, accents, features, forms | `src/brasa.config.ts`                                              |
| Design tokens, typography, motion               | `src/styles/global.css`                                            |
| UI strings                                      | `src/i18n/en.ts` and `src/i18n/pt-br.ts` (keep key sets identical) |
| Components                                      | `src/components/*.astro`; export MDX-usable ones from `mdx.ts`     |
| Blog / docs / authors / changelog               | `src/content/**` (frontmatter validated by `verify-mdx.mjs`)       |
| Page layouts                                    | `src/layouts/BaseLayout.astro`, `DocsLayout.astro`                 |
| Behaviour                                       | one of `src/scripts/*.ts`; prefer delegated listeners              |
| Tests                                           | `tests/e2e/*.spec.ts`; shared route list in `tests/e2e/helpers.ts` |
| Visual captures                                 | `docs/screenshots/` (generated by `tests/e2e/visual.spec.ts`)      |

## Conventions

- **Tokens, not literals.** Colors, type sizes, radii and motion come from
  `@theme` / semantic custom properties. No `#000` or `#fff`.
- **Both themes, both locales.** A new component must look right in dark and
  light and must have strings in both dictionaries.
- **Accessibility is a gate.** Every route is audited with axe in both themes,
  keyboard navigation must work, dialogs must trap focus, and reduced motion
  must disable animation.
- **JS budget.** Total JavaScript per page stays under 20 KB gzipped; the budget
  is asserted in `tests/e2e/budget.spec.ts`.
- **Search hygiene.** Prose is indexed via `data-pagefind-body`; code, file
  trees and navigation chrome are marked `data-pagefind-ignore`.
- **Screenshots are generated, not hand-edited.** Use the visual spec; captures
  set `data-capture` and reduced motion so the full page is visible.

## Reporting bugs

Include the route, viewport, theme, browser and a reproducible sequence. For
visual issues attach a screenshot from `docs/screenshots/` or a fresh capture.
