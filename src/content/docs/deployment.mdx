Brasa builds to a fully static `dist/` directory. There is no server runtime, no database and no environment-specific rendering path. If a host can serve files, it can host Brasa.

## The build contract

```bash
npm ci
npm run build
```

`npm run build` performs three steps in order:

1. `node scripts/verify-mdx.mjs` — validates every MDX frontmatter block.
2. `astro build` — renders routes, feeds and OG images, and runs Astro's content schemas.
3. `pagefind --site dist` — writes the search index to `dist/pagefind/`.

<Callout variant="danger" title="Do not skip the Pagefind step">
  Running `astro build` directly produces a site where the search dialog opens but reports an
  unavailable index. Always use `npm run build`, or add the Pagefind command to your host's build
  step explicitly.
</Callout>

## Base paths and links

Every internal URL goes through `import.meta.env.BASE_URL`: nav links, footer links, feed alternates, OG image paths, the favicon and the Pagefind module URL. That is why the same source builds at `/` and at `/brasa/` without a link audit.

<Callout variant="warning" title="A wrong base path fails quietly">
  The HTML still renders, but CSS, fonts, images and the search index 404. After a base-path change,
  open the deployed site and check the browser console, then run the "all internal links and assets
  resolve" Playwright test against the preview with the same `PAGES_BASE_PATH` set.
</Callout>

## Caching

Fingerprinted assets in `dist/_astro/` are safe to cache immutably. Generated OG images carry `Cache-Control: public, max-age=31536000, immutable` in their endpoint headers, but a static host serves the file directly — set a long cache lifetime for `/og/` in your host config if you want the same behavior.

`pagefind/` should be cached with the rest of the static output and invalidated on each deploy. Because the index is content-addressed internally, a stale index cannot be partially loaded.

## Verify the deployment

```bash
SITE_URL=https://your-domain.example PAGES_BASE_PATH=/ npm run build
npm run preview
npm test
```

Then check, on the live host: the theme toggle persists across a reload with no flash, `Ctrl+K` returns results, `/rss.xml` and `/feed.json` load, an OG URL returns a PNG, and the 404 page renders with its own status code.
