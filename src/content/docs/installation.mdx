Brasa is an Astro theme: you get the source, not a locked dependency. That means every component, token and content collection is editable in your repository, and the build stays a plain `astro build`.

## Requirements

- **Node.js 20 or newer.** CI uses Node 22; the build uses no Node-only APIs that are newer than 20.
- **npm.** The lockfile is committed, so `npm ci` is the reproducible install in CI and locally.
- **An editor with Astro support** is optional but recommended — content collections are typed.

<Callout variant="note" title="What you get">
The template ships the landing page, pricing, blog, docs, changelog shells, a 404 and a styleguide. Every page contains real demo copy for "Brasa Cloud", a fictional deploy-preview product — nothing in `src/` is a placeholder wall.
</Callout>

## Scripts worth knowing

| Command | What it does |
| --- | --- |
| `npm run dev` | Starts Astro's dev server with HMR. |
| `npm run build` | Verifies MDX frontmatter, builds the static site, then generates the Pagefind index into `dist/`. |
| `npm run preview` | Serves the built site — this is what the Playwright suite runs against. |
| `npm run check` | `astro check`: TypeScript and template diagnostics, zero warnings allowed. |
| `npm run lint` | ESLint with the Astro plugin. |
| `npm run format:check` | Prettier, including Astro and Tailwind class sorting. |
| `npm test` | Playwright e2e, axe audits, JS budget and reference screenshots. |

<Callout variant="warning" title="Always build before testing">
Playwright and Lighthouse run against `astro preview`, which serves `dist/`. If you change a component and run `npm test` without a fresh build, you are testing the previous output. CI builds first for exactly this reason.
</Callout>

## Verify the install

Run the full quality gate once before changing anything. A clean scaffold should pass all four steps:

```bash
npm run check
npm run lint
npm run build
npm test
```

The build prints `MDX frontmatter valid in … file(s)` before Astro starts. That guard catches the classic mistake of putting an `import` between the opening and closing `---` of an MDX file. If it fails, move the import below the closing delimiter.
