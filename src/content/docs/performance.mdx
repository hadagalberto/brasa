Speed is a feature here, measured rather than promised. The target from SPEC is Lighthouse **0.98 or better on all four categories** for the home page, a blog post, a docs page and pricing, with CLS under 0.02 and less than 20 KB of gzipped JavaScript per page.

## Why it is fast by construction

There is no React island runtime, no client-side router framework and no data fetching on navigation. `ClientRouter` handles View Transitions by swapping HTML and re-running small event-delegated modules on `astro:page-load`.

## JavaScript budget

`tests/e2e/budget.spec.ts` collects every external and inline script on a page, gzips the source and fails above 20 KB. The theme's own behavior module is small because it uses event delegation: one listener per event type, no per-element handlers.

<Callout variant="tip" title="Keep the budget when adding features">
Reach for event delegation and a single `astro:page-load` listener instead of component-scoped scripts. If a feature is heavy, load it on interaction — the Pagefind pattern applies to more than search.
</Callout>

## Fonts

Fraunces, Geist and Geist Mono are bundled from Fontsource as variable woff2 files, subset to latin and latin-ext with `font-display: swap`. The two Fraunces faces used by the hero are preloaded in `BaseLayout`:

```html
<link rel="preload" as="font" type="font/woff2" href="…fraunces-latin-opsz-normal.woff2" crossorigin />
<link rel="preload" as="font" type="font/woff2" href="…fraunces-latin-opsz-italic.woff2" crossorigin />
```

A layout test asserts those preloads exist and return 200, and another checks that all four faces actually resolve in the browser. Self-hosting removes a DNS lookup and a third-party connection from the critical path.

## Layout stability

CLS stays low because:

- The theme is applied by an inline script before first paint — no flash of the wrong palette.
- The pricing monthly/yearly toggle swaps text inside a fixed-height row.
- Images and OG cards have known dimensions; there are no injected hero illustrations.
- Reveal animations use `opacity` and `transform` only, never layout properties, and are off under reduced motion.
- The mobile menu is a fixed overlay, not a flow element that appears after load.

## Search without a runtime cost

Pagefind produces a static index at build time. The search dialog renders instantly with suggestions; only when the user types does the island import `/pagefind/pagefind.js`, fetch the relevant chunks and render result cards. A query on a 100-page site transfers a handful of small chunks rather than a client-side index of the whole site.

Dev-mode middleware, unminified scripts and missing Pagefind output all distort the score. If a Lighthouse assertion fails, inspect the JSON report in `.lighthouseci/` before changing code — the failing audit names the exact element or request.

## Keeping it fast

1. Do not add a UI framework for a single interaction; a vanilla island is enough.
2. Keep new fonts out unless they replace an existing face — each preload competes with the hero.
3. Generate images at build time or place them in `public/` with explicit dimensions.
4. Guard new animation with `@supports (animation-timeline: view())` and `prefers-reduced-motion`.
5. Re-run both Lighthouse presets after any change to head markup, fonts or the critical CSS path.
