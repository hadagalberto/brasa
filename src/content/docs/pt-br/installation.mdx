Brasa é um tema Astro: você recebe o código-fonte, não uma dependência travada. Isso significa que todo componente, token e content collection é editável no seu repositório, e o build continua sendo um simples `astro build`.

## Requisitos

- **Node.js 20 ou mais recente.** A CI usa Node 22; o build não usa nenhuma API exclusiva do Node mais nova que a 20.
- **npm.** O lockfile está versionado, então `npm ci` é a instalação reproduzível na CI e localmente.
- **Um editor com suporte a Astro** é opcional, mas recomendado — as content collections são tipadas.

<Callout variant="note" title="O que você recebe">
O template traz a landing page, preços, blog, documentação, os esqueletos do changelog, uma 404 e um guia de estilos. Toda página contém texto de demonstração real para a "Brasa Cloud", um produto fictício de prévia de deploy — nada em `src/` é um amontoado de placeholders.
</Callout>

## Scripts que vale conhecer

| Comando | O que faz |
| --- | --- |
| `npm run dev` | Inicia o servidor de desenvolvimento do Astro com HMR. |
| `npm run build` | Valida o frontmatter dos arquivos MDX, gera o site estático e depois cria o índice do Pagefind em `dist/`. |
| `npm run preview` | Serve o site já gerado — é sobre ele que a suíte Playwright roda. |
| `npm run check` | `astro check`: diagnósticos de TypeScript e dos templates, zero avisos permitidos. |
| `npm run lint` | ESLint com o plugin do Astro. |
| `npm run format:check` | Prettier, incluindo a ordenação de classes do Astro e do Tailwind. |
| `npm test` | Testes e2e com Playwright, auditorias axe, orçamento de JS e capturas de referência. |

<Callout variant="warning" title="Sempre faça o build antes de testar">
O Playwright e o Lighthouse rodam sobre `astro preview`, que serve `dist/`. Se você alterar um componente e rodar `npm test` sem um build fresco, estará testando a saída anterior. A CI faz o build primeiro exatamente por isso.
</Callout>

## Verificar a instalação

Execute a barreira completa de qualidade uma vez antes de fazer qualquer alteração. Um template limpo deve passar pelas quatro etapas:

```bash
npm run check
npm run lint
npm run build
npm test
```

O build imprime `MDX frontmatter valid in … file(s)` antes de o Astro iniciar. Essa proteção pega o erro clássico de colocar um `import` entre as linhas de abertura e fechamento do `---` em um arquivo MDX. Se falhar, mova o import para baixo do delimitador de fechamento.
